# 三分钟讲解提纲与答辩问题

以下为可编辑提纲，请结合本人真实理解和操作调整。

## 项目介绍（约 30 秒）

项目叫“星梦故事屋”，面向儿童和陪伴阅读的家长。用户输入名字、年龄和兴趣，选择主题，阅读带分支的故事。前半学期围绕同一森林故事增加了插画、语音、视频、素材检索和一个本地工作流原型。

## 技术架构与决策（约 90 秒）

网页使用 React、TypeScript 和本地存储。故事生成采用 Python 模板并输出结构化 JSON；森林绘本由内置图像工具生成四幅图，后三幅参考首图的角色外貌，Python 脚本负责排版。音频使用 Windows 自带语音，FFmpeg 把插画、配音、字幕和合成伴奏组合成视频。

选择离线规则和系统语音是为了降低运行成本和网络依赖，但牺牲了表达灵活性，也让系统受本机语音环境限制。素材检索是基于描述的 TF-IDF 文本向量匹配，不是 CLIP；第 7 周 LangGraph 是规则选择主题与固定节点编排，不是模型自主规划。它可以在初稿后让用户修改名字、场景或主题，再生成后续产物；图片目前复用已有素材。

## 工程和 AI 协作（约 60 秒）

项目分成前端、数据、引擎、语音、检索和工作流模块。故事 JSON 和用户输入有基础校验，生成案例使用新目录防止覆盖。AI 协助编写代码、提示词、图像和文档，并运行测试；本人应在答辩前核对代码、完整试听观看并准备说明自己的真实修改和理解。

## 可能的问题

**Q：是不是使用了大模型 API 生成故事？** 不是。当前按本人的成本偏好使用固定模板；这不满足第 2 周 API 调用的原要求。

**Q：图片检索是否使用了 CLIP？** 没有。当前根据图片的人工文字描述做字符 TF-IDF 匹配；支持自然语言输入但词汇泛化有限。

**Q：LangGraph 就意味着 Agent 可以自主规划吗？** 不意味着。这里主题由关键词规则选择，后续节点顺序固定，用户可以中途修改；没有模型自主决定工具调用。

**Q：图片里的主角会跟用户名字变化吗？** 不会重新生图。第 7 周森林案例复用旧插画，其他主题使用示意素材卡，因此可能与新故事不完全一致。

**Q：字幕如何同步？** 第 5 周使用第 4 周每段音频的实际帧数计算句子时间；第 7 周演示视频只按文字长度估算场景时长，不是逐句同步。

**Q：如何验证？** 说明自动化测试、浏览器交互检查和音视频格式检查；人工声音质量及教师评分需要单独核验。
